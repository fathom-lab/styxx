## 1. `styxx/v8/cert.py` + `styxx/v8/schema/*.json` — the envelope (§2, §2.1, §2.5, A.1)

```python
def digest_bytes(cert: dict) -> bytes            # raw 32: sha256(canonical_bytes(cert minus "id" and "sig"))
def compute_id(cert: dict) -> str                # "sha256:" + hex
def sign(cert: dict, private_seed: bytes) -> dict   # returns a NEW dict with id and sig set (sig over keys.tagged(CERT_TAG, digest)); refuses if issuer.key != encode_public(pub of seed)
def check(cert: dict) -> CertCheck               # dataclass: ok: bool, reasons: list[str] (empty when ok), type: str|None, id: str|None
    # checks, in order, collecting every failure: schema (envelope + per-type), id recompute, issuer.key decodes and validates (keys.decode_public → small-order/non-canonical rejected), signature over the tagged digest, materials hashes match (§2.3), every "sha256:<64hex>" string anywhere in subject/recipe/body appears in refs (§2.1 last bullet; A-09), refs roles valid for the type, no single-valued role named twice (every role except `run`/`result`/`robustness`, `cert.MULTI_ROLES` — C-DUPREF), integers within ±2**53, no NaN/Inf, and a fingerprint whose items reproduce `MockRunner`'s derivation without carrying `synthetic` (C-MOCK-2).
def embedded_ids(cert: dict) -> set[str]         # every value matching ID_RE anywhere under subject/recipe/body (recursive)
def refs(cert: dict) -> list[tuple[str, str]]    # [(role, id)]
def schema_errors(cert: dict) -> list[str]       # jsonschema Draft 2020-12; envelope schema then schema/<type>.json
def seal_commitment(salt32: bytes, body_to_reveal: dict) -> str   # "sha256:" + hex(sha256(SEAL_TAG || 0x00 || salt || canonical_bytes(body_to_reveal)))  (§7.2)
def version_ok(cert: dict, own: str = SCHEMA_VERSION) -> bool     # major.minor <= own (§2.5)
```
Schemas: `schema/envelope.json` (required: styxx, type, id, created (RFC 3339 Z), issuer{name,key}, subject, recipe, body, refs (array of {role, id}), sig; additionalProperties false at the top level) and one file per type constraining `body` (and `subject.kind`/`recipe` presence: fingerprint and battery require a subject and recipe; prereg/result/promotion/challenge/action/sublog require `subject` and `recipe` to be present but may be `{}`). `public` is NOT an envelope field: it is log metadata (§2.6 is implemented by the log; see errata in the spec header).
Subject schema: `kind: weights` requires model_family, hf_repo, revision, weights_sha256, config_sha256, tokenizer_sha256, generation_config_sha256, precision, environment{runtime{framework,version,backend}, hardware{gpu,driver,count}}; `kind: alias` requires model_family, provider, alias, region; optional observed_model_id, observed_at.
Recipe schema (§2.3): battery (ID_RE), decoding{temperature, top_p, max_new_tokens, stop (array), seed, batch_size (int ≥1), padding_side ("left"|"right")}, materials{chat_template, chat_template_source, system_prompt, env_lock}, chat_template_sha256, system_prompt_sha256, env_lock_sha256, harness{name,version,commit}, optional sae{loader,repo,revision,layers,attribution}.
Helpers: `identity_fields(subject) -> dict` (§2.2 S_identity per kind), `recipe_core(recipe) -> dict` (§2.3), `comparable(a, b) -> list[str]` (mismatched field names; empty means comparable; `precision` and `revision` differences are returned under the key `cross-subject` rather than as mismatches), `skew_fields(a, b) -> list[str]` (harness.version, env_lock_sha256), `challenge_validity(target, own) -> list[str]` (§9 rule 1: empty means `own` is a valid challenge to `target`; it is `comparable`, because every `cross-subject` field is an S_identity field and §9 wants them all equal — a second implementation is `challengeValidity` in `styxx/_data/v8_verify.js`).
Tests: round trip sign→check for every type with minimal valid bodies; every check reason is exercised by one negative test (tampered byte, wrong key, small-order key, missing ref, mismatched material hash, future schema version, NaN); `seal_commitment` reveal/verify; a fixture module `tests/v8_fixtures.py` exporting `make_cert(type, **overrides)`, `keypair()`, and minimal valid subjects/recipes for weights and alias — every later test file imports it.

## 5. `styxx/v8/runner.py` + `styxx/v8/runner_hf.py` — model access (§3)
