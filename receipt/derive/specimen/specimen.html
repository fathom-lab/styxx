What this does not show

HELD here means only this: each printed number follows, by the operation and the selection written in the claim, from the embedded rows, and those rows are byte for byte the file the page's maker read from the lab's repository. It does not mean the sentence is true.

  • That any accusation was right or wrong. Each row is the majority answer of a three-seat panel of models, written to the file by the lab's own harness. The page checks counting over those answers, nothing about the pull requests behind them.
  • That keys E1-000 to E1-099 are the accusations. That comes from the lab's recipe in papers/closed-model-frontier/external1_packet.py; the sealed key that names each item's arm is gitignored. The bytes do not say it.
  • That 100 is the right denominator. 26 of the 100 answers are UNSURE, and the lab's scorer counts every answer other than CONTRADICTED as not upheld. Over SUPPORTED and CONTRADICTED alone the same rows give 23 of 74. Those two figures come from the maker's own count, not from this page.
  • That 0.23 is the precision of path accusations. It is over all 100 sampled accusations. The README says 85 of them are path claims; a figure over those 85 needs a field from a second file (external1_packet.json), and derive v0 cannot join two files.
  • That the answers follow from the seats. This page does not read external1_panel_raw.json.
  • That the pinned hash is the lab's. The maker of this page wrote it in. Anyone who can edit this file can edit the rows, the pin and the checker together. Compare the hash with your own copy: git cat-file blob origin/main:papers/closed-model-frontier/external1_answers.json | sha256sum.
  • That another checker agrees. derive.js and derive.py were written by one agent from one draft text, beside each other. Their agreement on these rows shows the text was computed the same way twice, nothing more.
