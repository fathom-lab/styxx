# SEALS — the digests the lab will anchor, as bytes in the tree before any anchor exists

Fathom Lab · 2026-09-13 · **no anchor exists yet.** This file states what a seal is, which
digests are to be sealed, and the rule that decides the digest — so that `git grep` finds the
frozen hash in the repository and not only in an operator's notes.

## the rule

A seal is the sha256 of the **git blob** of the frozen file — the bytes as git stores them, LF —
computed as `git show <commit>:<path> | sha256sum`. Never the working copy: on a Windows checkout
made before a `-text` pin lands, the working copy carries CRLF and hashes differently (measured
2026-09-13: working copy `b8b7fe6b…`, blob `b3b98710…`, same file, unchanged since freezing). An
operator who hashes the working copy either stops for nothing or seals a digest no stranger can
reproduce. The memo text is built by `python -m styxx.clock memo <kind> <digest>` and nothing
else; `styxx.clock` takes the digest as written and refuses to fold it.

A seal proves that the digest existed no later than the block's time. It does not order a run
relative to that time: nothing in the sealed run's inputs depends on the seal (the deploy-scale
run uses the hand-frozen 48 canaries by design). A run whose canary draw comes from the seal's
own beacon would carry that ordering; that is the next PREREG's job, not this one's.
That PREREG exists since 2026-09-14 (`PREREG_checksum_beacon_draw_2026_09_14.md`, anchor #6 below): the
first seal here whose slot does work, because its block hash draws the 48 canaries of the run it
governs, so that run cannot precede its seal and a stranger checks the order from the bytes.

## the earliest-memo rule (added the same night)

A digest may be anchored more than once. Its seal is the **earliest** confirmed memo carrying it
from the creator wallet, and `python -m styxx.clock verify` enforces that by scanning the wallet's
own signature listing: a recorded transaction that is not the earliest reads
`EARLIER_MEMO_EXISTS`, and the beacon belongs to the earliest one's slot. Anchor each digest once.
If a transaction fails and is resent, the failed one does not count (only confirmed memos seal),
and the record must name the confirmed one.
